\begin{abstract}
We test whether the entropy-triggered patch boundaries of the Byte Latent Transformer (BLT) align with syntactic constituent starts in Python, C++ and English, beyond a density-matched null and structure-blind baselines. On a frozen held-out split of \nTestAll{} files, start F1 exceeds the null in every language (margins \MarginPy{}, \MarginCpp{}, \MarginEn{}; $p\le10^{-4}$), but BLT \RTwoAll{} against the strongest baseline: word-start splitting beats it on precision and recall at once, and indentation does better still in Python. Four further predictions fail as stated, and follow-up tests explain each. Precision is far below recall because the patcher proposes \xPredPerTargetEn{}--\xPredPerTargetPy{} boundaries per target. Prose aligns best (P3) because English constituents begin at words. The forced-opener reversal (P4) comes from scoring the wrong byte. The memory-unsafe residual (O5) exists only after conditioning on identifier entropy. A 14.3M-parameter student distilled from the 99.5M patcher keeps about 90\% of the teacher's margin. Entropy boundaries are a genuine but shallow signal that follows word and line onsets more than syntax.
\end{abstract}

\section{Introduction}
Byte-level models remove a fixed subword vocabulary, but they must still decide where to spend computation. BLT groups bytes into variable-length patches whenever a small next-byte model's entropy exceeds a threshold $\tau$ \citep{pagnoni-etal-2025-byte}. If those boundaries fall where syntactic constituents open, the allocation tracks structure. But rare identifiers, word onsets and formatting also raise entropy, so proximity alone cannot separate these explanations.

ESCAPE asks five questions from our proposal. O1/P1: do boundaries align with constituent starts beyond a null that keeps each file's own patch lengths? P2: more at starts than at ends? O2/P3: is code segmented differently from prose? P4: is alignment weaker for constructs whose opener is forced (\texttt{if}, \texttt{for}) than for open-ended ones? O3: does Python (indentation) differ from C++ (brackets)? O4: does alignment survive code noise? O5: does extra compute near memory-unsafe C++ survive conditioning on identifier unpredictability? This report completes O3--O5, explains the failed predictions with targeted tests, checks the statistics against clustering, parser-recovery and context artefacts, and, beyond the proposal, distils the patcher into a 7$\times$ smaller student evaluated under the same frozen protocol (\S\ref{sec:ext}).

Our contributions are: (i)~a byte-exact extraction pipeline that restores the 512-byte sliding window missing from the public conversion; (ii)~a calibration-first protocol with a density-matched null and structure-blind baselines as the burden of proof; (iii)~held-out results in three languages, every number regenerated from retained artefacts; and (iv)~follow-ups showing each failed prediction is a statement about which bytes carry entropy.

\section{Background and Related Work}
BLT segments bytes dynamically so that expensive latent computation operates over patches \citep{pagnoni-etal-2025-byte}. BPE fixes its merge table in advance \citep{sennrich-etal-2016-neural}; ByT5 and CANINE remove the vocabulary but process every byte uniformly \citep{xue-etal-2022-byt5,clark-etal-2022-canine}. Dynamic token pooling learned boundaries from conditional-entropy spikes in small models \citep{nawrot-etal-2023-efficient}; BLT applies an entropy threshold at scale, so each boundary is a claim that can be checked against external structure. Structural probes recover syntax from trained representations \citep{hewitt-manning-2019-structural,feng-etal-2020-codebert}, but need a trained probe. We ask whether an unsupervised compression signal with no parser in the loop recovers constituents as a side effect, as statistical word segmentation placed boundaries by predictability and was checked against observable word boundaries \citep{brent1999segmentation,goldwater2009word}. We use tree-sitter ASTs for code and benepar parses \citep{kitaev-klein-2018-constituency} for English, and, for the extension, online knowledge distillation \citep{hinton2015distilling}.

\section{Protocol}
\label{sec:protocol}
\paragraph{Data and checkpoint.} The frozen manifest has \nSamples{} samples: 8{,}000 Python functions from CodeSearchNet \citep{husain2019codesearchnet}, 8{,}000 C++ files from The Stack \citep{kocetkov2022stack} (the proposal's CodeSearchNet has no C++) and 300 WikiText-103 paragraphs \citep{merity2017pointer}, all restored and hash-verified. We load the 99.5M-parameter patcher of \texttt{itazap/blt-1b-hf} (revision \texttt{91aa6b8e}) in float32 rather than the proposal's bfloat16 (bf16 weights upcast losslessly) with $\tau=1.3354$ nats, no length cap, and the reference 512-byte sliding window in 8{,}192-token chunks. Six of eight fidelity gates passed as declared, two criteria were amended, and the amended set \FidelityAda{} on the cluster stack. The logits agree with an independent re-implementation to $1.05\times10^{-4}$, with identical boundaries.

\paragraph{Metric, null and baselines.} Entropy at byte $i$ is $H_i=-\sum_v p_\theta(v\mid x_{<i})\log p_\theta(v\mid x_{<i})$ over 260 symbols. Predictions are interior entropy boundaries; with no length cap, every one after the forced first byte is entropy-triggered. Targets are the unique starts of non-wrapper constituents (outermost wins ties), excluding byte 0 and file end: statement- and expression-level tree-sitter nodes in code and benepar phrases in English. Parser offsets are round-tripped to UTF-8 byte offsets and validated. Memory-unsafe regions for O5 are C++ statements containing pointer dereference or address-of (\texttt{*}, \texttt{\&}), \texttt{new}, \texttt{delete}, unsafe C library calls, or unsafe casts. Maximum-cardinality one-to-one matching within $k$ bytes gives pooled P, R and F1. Each language is split 20/80 by seeded SHA256 rank into calibration and test files, and only calibration files choose $k\in\{0,1,2,4,8\}$, by the median per-file F1 margin over the null; $k=0$ was selected everywhere. The null shuffles each file's (length, reason) patch pairs except the last, which stays fixed so that file end is never a boundary, and so it preserves the patch-length multiset and boundary count. We use \nPerm{} seeded permutations per file and \nBoot{} paired file-bootstrap replicates. A structural reading must also beat boundaries at every newline, at indentation changes, and at every word start under the same targets and matching. We call this frozen protocol C-v1; the frozen teacher run was scored once and no primary number changed after the mid-submission. Later test-split scorings are either pre-registered extension runs (\S\ref{sec:ext}), each scored once, or sensitivity and exploratory runs ($k=1,2$, the O4 rate sweep, HF full attention, the follow-up arms, a $\tau$ grid) that selected no setting.

\paragraph{P1 and the structure-blind burden.} Start F1 exceeds the null in every language (Table~\ref{tab:main}), with ratios of 4--5$\times$ in code. Against the strongest structure-blind baseline, however, BLT \RTwoAll{} (Table~\ref{tab:baselines}): Python \VsBasePy{} \VsBaseCIPy{} against indentation, C++ \VsBaseCpp{} against word starts, and English \VsBaseEn{} against word starts. At BLT's density the F1 comparison is partly settled before alignment enters: with $r$ predictions per target, F1~$\le 2/(r+1)$, which caps BLT at \xFoneCapPy{}, \xFoneCapCpp{} and \xFoneCapEn{}, below each strongest baseline. A density-free comparison agrees: word-start splitting places fewer boundaries than BLT yet beats it on precision \emph{and} recall in every language (Python \xWordPPy{}/\xWordRPy{} against \PrecPy{}/\RecPy{}). Span IoU, the proposal's secondary metric, agrees (Appendix Table~\ref{tab:iou}).

\paragraph{Precision versus recall.} The proposal's mechanism predicted precision above recall: cheap interiors and forced closing delimiters would rarely trigger, so boundaries would be few and well placed. Instead precision \PrecRecAll{} (Python \PrecPy{}/\RecPy{}; C++ \PrecCpp{}/\RecCpp{}; English \PrecEn{}/\RecEn{}). Since $H\le\log B$, every boundary sits where at least $e^{\tau}\approx3.8$ continuations were live. Identifier interiors, strings and comments are flat without being syntactic, so predictions outnumber targets \xPredPerTargetPy{} to one in Python, \xPredPerTargetCpp{} in C++ and \xPredPerTargetEn{} in English, which caps precision while the same density guarantees high recall. P2 holds in the predicted direction: end margins are negative (\EndMarginPy{}, \EndMarginCpp{}, \EndMarginEn{}), so closing delimiters are anti-aligned.

\paragraph{Why P3 came out reversed.} The proposal predicted large BPP variance in code and near-chance alignment in prose. Mean bytes per patch (BPP) is \BppCpp{} in C++, \BppPy{} in Python and \BppEn{} in English. The first half holds: within-file BPP variance is \BppVarCpp{} in C++ and \BppVarPy{} in Python against \BppVarEn{} in English, because boilerplate stretches alternate with dense logic. The second half fails: the prose margin \MarginProse{} exceeds the code margin \MarginCode{}. Two facts explain this. First, a benepar constituent always begins at a word, and the patcher fires at word onsets, so the word-start rule alone reaches F1 \StrongestFoneEn{} in English. Second, normalising does not rescue P3. Because the null keeps BLT's boundary count, F1 over null F1 equals $R/R_0$, which cannot exceed $1/R_0$ (\xRatioCapPy{}, \xRatioCapCpp{}, \xRatioCapEn{}), close to the mean patch length. The raw ratio favours code (\xRatioPy{}$\times$ Python, \xRatioCpp{}$\times$ C++, \xRatioEn{}$\times$ English) only because code patches are longer. Chance-corrected recall $(R-R_0)/(1-R_0)$ has no such ceiling and ranks English first (\xKappaEn{} against \xKappaPy{} and \xKappaCpp{}). P3 is reversed: prose aligns best, and it does so at word onsets.

\paragraph{Why P4 came out reversed, and what the forced bytes do.} By type, forced openers have larger start-recall margins than open-ended constructs (Appendix Table~\ref{tab:types}; mean \DetMarginPy{} vs.\ \OpenMarginPy{} in Python, \DetMarginCpp{} vs.\ \OpenMarginCpp{} in C++), the opposite of P4. The mid-report noted that a start boundary sits \emph{before} the keyword, where the choice of statement is still open. The forcing the proposal predicted applies to the bytes after the keyword, so we tested those directly. For every primary target start $s$ we take its first token (the identifier run at $s$: the keyword for forced openers) and score the boundary rate at fixed positions against the same \nPerm{} null draws as the frozen scorer, so the start rows \xPosCheck{} the frozen type recalls exactly (Appendix Table~\ref{tab:p4pos}). The rest of the keyword is segmented below chance (Python \xKwDetPy{}, C++ \xKwDetCpp{}), and the byte right after it almost never starts a patch (rate \xPostKwRateDetPy{} and \xPostKwRateDetCpp{} against null rates of \xOffNullPy{} and \xOffNullCpp{}). The boundary reappears where choice reopens. In Python the next non-space byte begins the condition, and its boundary rate is \xNextRateDetPy{} (\xNextDetPy{}). In C++ the next byte is the equally forced \texttt{(}, and the boundary moves to the condition at offset four (rate \xOffDetCppIV{}; Figure~\ref{fig:offsets}). P4's mechanism therefore holds at the bytes it is about: once a keyword is committed, its continuation is predictable and is segmented far below chance. A start-offset metric cannot see this: the start byte is where forcing has not yet happened.

\paragraph{O3: Python versus C++ on a common depth scale.} Raw tree-sitter depth is not comparable across languages, because C++ statements sit under more scaffolding nodes. We therefore count depth in constituents, as the number of stored target-type nodes that strictly enclose a node, and also normalise it within each file (Figure~\ref{fig:depth}). On this common scale all three languages align most at the outermost constituents. From one enclosing constituent to seven, the margin falls from \xDepthOnePy{} to \xDepthSevenPy{} in Python, from \xDepthOneCpp{} to \xDepthSevenCpp{} in C++, and from \xDepthOneEn{} to \xDepthSevenEn{} in English; C++ falls further, to \xDepthEightCpp{}, at eight or more. Python exceeds C++ at every depth both languages share and at every relative-depth decile. English is nearly flat below the top levels. The indentation-versus-brackets contrast that O3 asked about shows up in the baselines rather than in the depth profile. In Python the indentation rule is the strongest baseline, because indentation \emph{is} the grammar. In C++ word starts are the strongest baseline, and BLT's deficit to them (\VsBaseCpp{}) is smaller than its deficit to indentation in Python (\VsBasePy{}).

\paragraph{O4: robustness to noise, by rate.} At the frozen rates (\OFourRate{} of lines or keywords, \OFourCaseRate{} of identifiers) every noised margin stays at or above \OFourMinMarginPy{} (Python) and \OFourMinMarginCpp{} (C++), and the largest drop is \OFourWorstDmPy{} for \OFourWorstPy{} noise in Python (Appendix Table~\ref{tab:o4}). The perturbations are the proposal's: missing semicolons (C++), indentation changes, camelCase$\leftrightarrow$snake\_case inversion, and keyword typos. To test whether this ``graceful degradation'' depends on the rate, we rebuilt the same \xOFourSweepFiles{} files per language with each noise type at 5, 10, 20 and 40\% (case inversion at 25, 50 and 100\%) and rescored them with the unchanged O4 scorer (Figure~\ref{fig:o4}). Indentation noise does by far the most damage, growing with the share of lines touched: from \xOFourIndentLoPy{} at 5\% to \xOFourIndentHiPy{} at 40\% in Python and from \xOFourIndentLoCpp{} to \xOFourIndentHiCpp{} in C++, the signature of a patcher whose statement boundaries ride on line layout. At 40\%, keyword typos cost \xOFourTypoHiPy{} (Python) and \xOFourTypoHiCpp{} (C++), missing semicolons \xOFourSemiHiCpp{}, and renaming at most \xOFourCaseMaxPy{} and \xOFourCaseMaxCpp{}. Typos also lower bytes per patch (\xOFourTypoBppPy{}, \xOFourTypoBppCpp{} at 40\%). Every noised margin stays at or above \xOFourSweepMinMargin{}.

\paragraph{O5: is there a semantic residual near memory-unsafe code?} We first audited the region labels (\texttt{docs/O5\_LABEL\_AUDIT.md}): re-running the queries reproduced \xAuditRepro{} frozen regions exactly, and an independent lexical labeller agreed on \xAuditAgree{} audited statements. Following the proposal's compute-profiling metric we model two outcomes, boundary density and inverse-BPP compute density. The frozen regression gives unsafe statements \xOFiveFull{} \xOFiveFullCI{} extra boundaries per byte after file fixed effects and identifier controls. Refitting it as a nested sequence (our refit \xOFiveCheck{} the frozen coefficients) changes the reading (Appendix Table~\ref{tab:o5}). With file fixed effects only, unsafe statements receive \emph{fewer} boundaries (\xOFiveRaw{} \xOFiveRawCI{}), because they use more predictable identifiers. The positive coefficient appears only after conditioning on identifier entropy, and identifier share alone does not flip it. The conditional effect is \xOFiveRel{} of the comparison statements' mean density. On inverse BPP, the proposal's compute metric, the file-fixed-effects estimate is null (\xOFiveRawBpp{} \xOFiveRawBppCI{}). O5 therefore finds no evidence that the patcher allocates extra compute to memory risk: what survives the confound is a small conditional effect, and the unconditional effect is negative or null.

\paragraph{Are the intervals too narrow?} The \nTestPy{} Python test functions come from only \xRepoN{} repositories. Resampling repositories widens the Python interval \xRepoWiden{}$\times$, from \xFileCI{} to \xRepoCI{}, which still excludes zero. Tree-sitter error recovery affects \xErrShare{} of C++ test files; their margin differs from clean parses by \xErrDiff{} \xErrDiffCI{}. Files over 8{,}191 bytes, whose context resets at chunk edges, are \xLongShare{} of C++ test files but \xLongBytes{} of its bytes, and their margin differs by \xLongDiff{} \xLongDiffCI{}. Under $k=1,2$ the margins shrink and BLT never overtakes the strongest baseline. HF's native full-attention mode, not faithful beyond 512 bytes, cuts the margin to \xHfMarginPy{} (Python), \xHfMarginCpp{} (C++) and \xHfMarginEn{} (English), against \xHfSwaMarginPy{}, \xHfSwaMarginCpp{} and \xHfSwaMarginEn{} with the restored window, so every result depends on that restoration.

\section{Beyond the Proposal: a Distilled Patcher}
\label{sec:ext}
The proposal needed no training. As a separately pre-registered extension, we ask whether a much smaller byte model can reproduce the patcher's boundaries and whether structural alignment survives distillation. A 14.3M-parameter student (384 dimensions, 8 layers, 6 heads, BLT-style byte transformer) was trained from scratch by online distillation, $\alpha\,\mathrm{CE}+(1-\alpha)T^2\,\mathrm{KL}(p_T\Vert p_S)$ with $\alpha=0.1$ and $T=2$, on $\le$512-byte windows of a disjoint extension corpus. That corpus has 29{,}000 files: CodeSearchNet functions from repositories not in the evaluation set, WikiText paragraphs from unused articles, and Stack C++ from other repositories, split by repository or article. On held-out extension windows the student's boundaries reach F1 \xDistFone{} against the teacher's. Dropping the teacher ($\alpha=1$, same data, seed and schedule) reaches \xAlphaFone{}, and placing a boundary at every word start reaches \xWordVsTeacherFone{}. The $\alpha=1$ student predicts the true next byte better (\xAlphaBpb{} vs.\ \xDistBpb{} bits/byte; teacher \xTeacherBpb{}), so distillation trades a little compression for agreement with the teacher's segmentation.

\paragraph{Held-out alignment.} We extracted the student on all 16{,}300 corpus files with stride-1 fresh 512-byte windows, the regime it was trained in. The extractor first reproduced the committed golden-fixture scores on the cluster GPU (largest F1 deviation \xGateMaxDev{}). The student then went through the frozen C-v1 pipeline with its own calibration record, which again selected $k=0$ everywhere (Table~\ref{tab:student}). It keeps \xStuRetainPy{}, \xStuRetainCpp{} and \xStuRetainEn{} of the teacher's margin (Python, C++, English). The paired deficit is small but resolved (\xStuDiffPy{} \xStuDiffCIPy{} in Python), and the student, like the teacher, stays below the baselines. A control on 300 test files per code language restricts the \emph{teacher} to the student's fresh 512-byte windows. This costs \xTfiveDiffPy{} \xTfiveDiffCIPy{} (Python) and \xTfiveDiffCpp{} \xTfiveDiffCICpp{} (C++) of F1, about \xTfiveSharePy{} and \xTfiveShareCpp{} of the student's deficit. The student's forward pass is \xEffForward{}$\times$ faster than the teacher's on one \xEffGpu{}.

\paragraph{Threshold and tolerance.} The checkpoint's $\tau$ was set for compression, not alignment. We swept $\tau\in\{0.8,1.0,1.335,1.7,2.0,2.5\}$ on calibration files only; $\tau^*$ was pre-registered as the argmax of the median per-file margin, ties to the smaller $\tau$. For the teacher $\tau^*=\xTauStarTeacherPy{}$ in all three languages (calibration gain \xTauGainTeacherPy{} in Python), and for the student $\tau^*=\xTauStarStudentPy{}$ (Python), \xTauStarStudentCpp{} (C++) and \xTauStarStudentEn{} (English; Figure~\ref{fig:tau}). The student's English optimum sits at the edge of the grid, where its entropy runs higher than the teacher's. The grid was not extended, and each language was confirmed at its own $\tau^*$. After re-freezing $k$ under $\tau^*$, each model's confirmatory test run was scored exactly once (Table~\ref{tab:tau}): the teacher's margin rises to \xTauConfTeacherPy{} (Python), \xTauConfTeacherCpp{} (C++) and \xTauConfTeacherEn{} (English), a paired gain of \xTauPairGainTeacherPy{} \xTauPairGainCITeacherPy{} in Python, and it remains below the strongest baseline (\xTauConfVsBaseTeacherPy{}, \xTauConfVsBaseTeacherCpp{}, \xTauConfVsBaseTeacherEn{}). The student's margin at its own $\tau^*$ is \xTauConfStudentPy{}, \xTauConfStudentCpp{} and \xTauConfStudentEn{}, also below the baselines. A later test-file run of the whole grid, which selects nothing, peaks at the same $\tau^*$ . Fewer, higher-entropy boundaries raise precision and margin, but no threshold makes entropy a parser.


\paragraph{The confirmatory English test.} Because the 300 evaluation paragraphs were inspected during exploration, we pre-registered a holdout of the 120 lowest-ranked WikiText articles that neither evaluation nor distillation used, \xHoldFiles{} paragraphs with benepar structure, and scored it once after team sign-off (Table~\ref{tab:holdout}). The teacher's margin is \xHoldTeaMargin{}, against \MarginEn{} on the evaluation paragraphs, and the student's is \xHoldStuMargin{}. Both stay below word starts (\xHoldTeaVsWord{} and \xHoldStuVsWord{}), so the English findings replicate on untouched text.

\paragraph{Byte balancing and domain adaptation.} Two exploratory follow-ups ran on the 600-file code subset of the earlier control plus the English test split. C++ is 73\% of the distillation bytes. A student trained with every domain drawn to an equal expected byte share agrees with the teacher on held-out windows at F1 \xBalWinFone{} (distilled student: \xBalRefWinFone{}); its margin differs from the distilled student's by \xBalDiffPy{} \mbox{\xBalDiffCIPy{}} (Python), \xBalDiffCpp{} \mbox{\xBalDiffCICpp{}} (C++) and \xBalDiffEn{} \mbox{\xBalDiffCIEn{}} (English), so balancing trades code for prose. The pre-registered adaptation arm initialises the teacher architecture from the patcher and trains it with the same loss and data; its margin differs from the student's by \xAdaptDiffPy{} \mbox{\xAdaptDiffCIPy{}}, \xAdaptDiffCpp{} \mbox{\xAdaptDiffCICpp{}} and \xAdaptDiffEn{} \mbox{\xAdaptDiffCIEn{}}. The criterion, a gain larger than the width of the student's confidence interval in at least two domains, is \xAdaptVerdict{} (\xAdaptWins{} of 3): in code, fine-tuning only recovers the unadapted teacher read through the same windows.

\section{Verdict on H1 and Deliverables}
{\sloppy The proposal defined support for H1 as: P1 clears both baselines with non-overlapping intervals, P2 holds in the predicted direction, P3 shows a code/prose dissociation, and P4's stratification appears. Judged that way, H1 is not supported: only P2 holds. P1 clears the null (H0) but not the whitespace and word-start baselines; P3 and P4 are reversed; and precision is below recall. All five proposal deliverables are delivered: (1)~the extraction pipeline (\texttt{stream\_a}); (2)~the tree-sitter and benepar mapping engine with the memory-unsafe queries (\texttt{stream\_b}); (3)~the evaluation harness (\texttt{escape\_scoring}, \texttt{escape\_eval}); (4)~the entropy heatmaps and BPP profiles; and (5)~this report and the presentation, covering O1--O5. Code, per-file results, tests and the build that regenerates every number ship in \texttt{Trimax-Final.zip}; the three distilled students are on Hugging Face (\url{https://huggingface.co/Devatri/escape-blt-entropy-student}; with the suffixes \href{https://huggingface.co/Devatri/escape-blt-entropy-student-alpha1}{\texttt{-alpha1}} and \href{https://huggingface.co/Devatri/escape-blt-entropy-student-balanced}{\texttt{-balanced}}, the $\alpha{=}1$ control and the byte-balanced student), with checkpoints and training curves in the W\&B project \href{https://forge.coreweave.com/wandb/kanhadivyansh123-iiit-hyderabad/escape-blt-patching}{\texttt{escape-blt-patching}}.\footnote{\url{https://forge.coreweave.com/wandb/kanhadivyansh123-iiit-hyderabad/escape-blt-patching}}}

\section{Conclusion}
BLT's entropy boundaries sit at constituent starts \xRatioEn{} to \xRatioPy{} times more often than a null with the same patch lengths, in all three languages, on held-out files and on a pre-registered English holdout, and a 7$\times$ smaller distilled student keeps about 90\% of that margin. Yet indentation and word-start rules segment better at every threshold. The failed predictions have mechanical causes: several boundaries per target (precision), word onsets (P3), forcing that acts after the opener (P4), and a residual that appears only after conditioning on identifier entropy (O5). Entropy-based patching tracks uncertainty, which syntax shapes without being what it measures.

\section*{Ethical Considerations}
We analyse existing text and code without executing corpus programs. Dataset provenance and licences accompany restored inputs.

\section*{Limitations and Future Work}
\paragraph{Limitations.} The checkpoint is a third-party conversion with a sliding window we restored; bitwise identity with the gated original was not tested, and its patch-length distribution was not compared with statistics published for the original model, as the proposal planned. English targets are predicted benepar parses, and the 300 evaluation paragraphs were seen during exploration, so only the holdout is confirmatory. The O5 labels are syntactic (no types, aliasing or bounds) and restricted to clean-parse C++. The student was evaluated at one size, with the rolling extractor only. The $\alpha=1$ control and threshold sweep share the corpus and seed, so between-seed variance is not measured. The follow-up arms used a 600-file code subset and the English test split. We did not evaluate a subword-tokenizer baseline, so O4 shows robustness only to the tested perturbations. Intervals are not corrected for multiple comparisons, so small effects such as the byte-balanced student's C++ difference may not survive. English intervals resample paragraphs, not articles; C++ intervals are not clustered by repository.
\paragraph{Future work.} A parser-supervised teacher was not run. Open items are a subword-tokenizer baseline for O4, several student seeds, full-corpus scoring of the follow-up arms, a single-pass student kernel, and a bitwise check against the gated checkpoint.
