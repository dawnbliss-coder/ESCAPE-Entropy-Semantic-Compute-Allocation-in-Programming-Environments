\begin{abstract}
We investigate whether entropy-triggered boundaries in the Byte Latent Transformer (BLT) align with syntactic constituent starts beyond a density-matched null. Project ESCAPE compares Python, C++, and English prose. We restore the patcher's 512-byte sliding window, extract entropies for all \nSamples{} files, freeze the matching tolerance on a calibration split, and score the held-out split with one-to-one matching against \nPerm{} permutations of each file's own patch lengths. Held-out start F1 \POneAll{} (Python \FonePy{} vs.\ \FoneNullPy{}; C++ \FoneCpp{} vs.\ \FoneNullCpp{}; English \FoneEn{} vs.\ \FoneNullEn{}). Against the strongest structure-blind baseline (indentation or word starts), however, BLT \RTwoAll{}. By constituent type, forced-opener constructs such as \texttt{if} and \texttt{def} align more strongly than open-ended ones, contrary to our prediction. Under injected code noise, alignment degrades only slightly, while noise lowers bytes per patch. Entropy is a surface statistic, and none of these results is evidence of semantic understanding.
\end{abstract}

\section{Introduction}
Byte-level models remove a fixed subword vocabulary, but computation still needs to be allocated across long input sequences. BLT groups bytes into variable-length patches using a small next-byte entropy model \citep{pagnoni-etal-2025-byte}. A boundary at the start of a syntactic constituent could indicate that this allocation tracks structure. Rare identifiers, word starts, and formatting can also induce boundaries, so proximity alone cannot distinguish these explanations.

ESCAPE asks whether entropy-triggered boundaries align with constituent starts more than a null with the same patch-length distribution and boundary count (P1). We also ask whether they align more at starts than at ends (P2), more in code than in prose (P3), and less for constructs whose opening is forced than for open-ended ones (P4). A further question is whether any extra patching near memory-unsafe C++ persists after identifier controls. These are empirical hypotheses: entropy bounds branching ($H\le\log B$) but is neither a grammatical branching factor nor a measure of program semantics. This report gives held-out results for P1--P4 against both the null and structure-blind baselines, span IoU as a secondary metric, and robustness to code noise (Objective 4).

This submission contributes (i) a byte-exact extraction pipeline for the BLT patcher that restores the reference 512-token sliding window missing from the public Hugging Face conversion, (ii) a calibration-first scoring protocol whose null preserves each file's patch-length multiset and boundary count and whose structure-blind baselines make line and word segmentation the burden of proof, and (iii) held-out measurements across three languages with robustness results, all reproducible from retained per-byte artifacts. Section~\ref{sec:protocol} fixes the protocol; Section~4 describes data and checkpoint; Section~5 reports results.

\section{Background and Related Work}
BLT dynamically segments byte sequences so that expensive latent computation operates over patches \citep{pagnoni-etal-2025-byte}. Our analysis concerns its entropy patcher, not downstream generation accuracy.

\paragraph{Subword tokenization and its failure modes.}
Standard pretraining front ends fix a vocabulary before the model sees data. BPE learns a merge table over a corpus and then applies it uniformly \citep{sennrich-etal-2016-neural}. The resulting segmentation is known to align poorly with morphology, to segment rare or multilingual tokens unstably, and to spend the same number of units on boilerplate as on subtle logic, because the compression ratio is frozen in advance. Interpretability work on tokenizers has therefore concentrated on the vocabularies themselves; whether a learned segmentation corresponds to anything independently verifiable is rarely asked, because a static merge table is not a claim a model makes.

\paragraph{Tokenization-free models.}
ByT5 removes the vocabulary but not the uniformity: every byte is processed with equal compute \citep{xue-etal-2022-byt5}, and CANINE substitutes learned character hashing with the same uniform treatment \citep{clark-etal-2022-canine}. Neither architecture decides, at inference time, where a boundary belongs. BLT is the first architecture at scale in which segmentation is both byte-level and dynamic: each boundary is a claim the model makes about its own next-byte uncertainty, which is precisely why it can be checked against external structure.

\paragraph{Structural probing.}
It is established that trained representations encode syntax: structural probes recover parse trees from contextual embeddings \citep{hewitt-manning-2019-structural}, and code pretraining objectives yield embeddings from which program structure is recoverable \citep{feng-etal-2020-codebert}. These results, however, require either a probe trained for the purpose or a model trained with code-specific objectives. None of this literature asks the question ESCAPE asks: whether an unsupervised, compression-only signal with no parser in the loop recovers constituent structure as a side effect. The BLT paper reports efficiency and downstream accuracy but never inspects whether the induced patches line up with structure that can be verified independently; that is the gap this work addresses, and code is the natural test bed because its parse trees provide machine-checkable ground truth.

\paragraph{Statistical segmentation precedents.}
Using local predictability to decide where units begin is an old idea outside neural models: unsupervised word segmentation infers boundaries from statistical cues such as prediction strength and transition probabilities \citep{brent1999segmentation, goldwater2009word}. BLT moves this intuition inside a byte-level neural model, but the induced boundaries have not been checked against independently verifiable structure - which is precisely the check the segmentation literature has always had, since word boundaries are directly observable. ESCAPE applies the same check to the patcher: the AST is never seen by the model and exists only as evaluation ground truth.

We use code AST starts and predicted English constituent starts as external structural references. Python samples come from CodeSearchNet \citep{husain2019codesearchnet}, and C++ uses a subset of The Stack \citep{kocetkov2022stack}. English paragraphs come from WikiText-103 \citep{merity2017pointer} and are parsed with benepar \citep{kitaev-klein-2018-constituency}. These reference structures differ in granularity and reliability, motivating language-specific calibration and reporting.

\section{Evaluation Protocol}
\label{sec:protocol}
\paragraph{Byte contract and metric.} All positions are frozen UTF-8 byte offsets; spans are half-open. Versioned JSONL interfaces carry sample metadata and hashes, patcher outputs, ground-truth nodes, and region annotations. Validators check joins, hashes, lengths, patch tiling, and entropy coverage. Entropy at byte $i$ is the model's global Shannon entropy
\begin{equation}
H_i=-\sum_{v\in\mathcal{V}}p_\theta(v\mid x_{<i})\log p_\theta(v\mid x_{<i})
\end{equation}
over its 260 output symbols, in nats. Predictions are interior boundaries labelled \texttt{entropy}. Targets are unique starts of eligible, non-wrapper, positive-length nodes, excluding byte zero and file end. Maximum-cardinality one-to-one matching pairs predictions and targets within $k$ bytes. With $T$ matches, $P$ predictions and $G$ targets, precision is $T/P$, recall $T/G$ and F1 $2T/(P+G)$, pooled across files. Ends are scored the same way.

\paragraph{Frozen tolerance and null.} Each language is split at the file level by a seeded SHA256 rank: 20\% calibration, 80\% test. Only calibration files evaluate $k\in\{0,1,2,4,8\}$, and we choose the $k$ maximizing the median per-file F1 margin over the null, ties to the smaller $k$. The hashed record is verified at scoring, and there is no test-time override. For each file, $H_0$ shuffles the (length, termination) pairs of all patches except the last, which stays in place so that file end never becomes a scored boundary, and rebuilds the endpoints. This preserves file length, the patch-length multiset and the number of entropy boundaries. Each of \nPerm{} seeded permutations shuffles every test file independently. We report the null mean, the one-sided permutation value, and paired file-bootstrap 95\% intervals (\nBoot{} replicates).

Fixing the final patch matters more than it looks: if the last patch were shuffled too, file end would become a candidate boundary in some resamples, and a file whose final bytes are a closing delimiter or punctuation would systematically penalize the null, inflating BLT's margin. The fixed-endpoint construction removes that artefact by construction, and because the multiset of lengths is otherwise preserved exactly, the null is the strongest density-matched baseline available from the file's own outputs.

The calibration curve is monotone and decisive: the median per-file F1 margin over the null shrinks as $k$ grows, from 0.121 to 0.010 in Python, 0.126 to 0.014 in C++ and 0.357 to 0.002 in English across the grid $\{0,1,2,4,8\}$, so the criterion selects $k=0$ for all three languages. Selecting the strictest tolerance is a statement about the data, not a choice to hide behind: larger tolerances would close the gap between BLT and the null precisely because the null's density, not its placement, is what a loose tolerance rewards.

\paragraph{Structure-blind baselines.} Under the same targets, $k$ and matching, we score boundaries after every newline, at indentation changes, and at every word start. A structural reading requires BLT to beat these, since most code constituents begin after a line break and most prose constituents begin at a word. We report BLT minus baseline F1 with a paired file bootstrap.

\paragraph{Matching and depth stratification.} One-to-one matching prevents a single prediction from crediting two nested targets; with any-match counting, nested starts at nearby offsets could inflate recall, and the two conventions would diverge for $k>0$. Alignment is additionally computed per raw tree-sitter depth stratum, with recall as the per-stratum metric because all strata share the same prediction set, so precision differences are definitional rather than empirical. Raw depth is not comparable across languages: Python and C++ carry very different amounts of grammar scaffolding per statement, and the benepar constituent trees are collapsed differently again. Cross-language depth normalization is therefore left to the final submission; per-depth curves here are within-language evidence about where in the tree boundaries concentrate.

\paragraph{Replication artefacts.} Two implementation-level effects are measured rather than assumed away. First, the patcher processes byte streams in 8{,}192-token chunks under the restored window, so files longer than 8{,}191 bytes have positions whose context is truncated at a chunk edge; the BPP summary records these positions per file, and they are reported as part of the run metadata. Second, the entropy threshold is compared strictly in float64 against the stored float32 entropies, so every trigger decision is reproducible from the saved arrays alone, which the cross-process reproducibility check exploits.

\paragraph{Worked example.} The patcher's segmentation of the first lines of a short Python function, with patch starts marked by \texttt{|}:

\begin{quote}\small\ttfamily
d|e|f |f|i|b|onacci|(|n|):\\
\quad|if n |< |2|:\\
\quad\quad|return |n|\\
\quad|return |fibonacci(n |- 1) |+ |fibonacci(n - 2)
\end{quote}

Boundaries fall at statement starts after indentation (\texttt{if}, \texttt{return}), at function arguments, and at nearly every byte inside the first occurrence of an identifier, while a token already committed stays whole on reuse (\texttt{fibonacci(n} in the final line is a single patch). The same qualitative pattern holds in C++ - boundaries open statements after delimiters and indentation, identifiers split at first use and stay whole afterwards, and boilerplate stretches produce long patches, which is why C++ files carry the largest within-file BPP variance. The example shows all three sources of entropy at once: structure, lexical novelty, and formatting - which is why the baselines of Section~\ref{sec:protocol} are needed to separate them.

\paragraph{Provenance.} Reproducibility is enforced mechanically rather than by convention. The frozen run directory carries per-file SHA-256 sums; the scoring configuration, seeds and file identities are recorded with every table; and the report's numbers are generated by a build script that reads the retained artifacts and refuses synthetic inputs. The corpus manifest pins every file's bytes by hash, and the calibration record stores the calibration file identities and the selected tolerance, so a from-scratch re-run either reproduces the reported numbers or fails loudly.

\section{Data and Checkpoint}
The frozen manifest has \nSamples{} samples: 8{,}000 Python functions (CodeSearchNet), 8{,}000 C++ files (The Stack, smol) and 300 English paragraphs (WikiText-103). All bytes were restored and verified against stored hashes. Calibration used \nCalPy{}/\nCalCpp{}/\nCalEn{} files and testing \nTestPy{}/\nTestCpp{}/\nTestEn{} (Python/C++/English). The selected tolerances were $k=\kPy$, $\kCpp$ and $\kEn$.

We use the Hugging Face conversion \texttt{itazap/blt-1b-hf} (revision \texttt{91aa6b8e}), loading only its 99.5M-parameter patcher. It runs in float32 with threshold 1.3354 nats, no length cap, and the reference 512-token sliding window and 8{,}192-token chunks, which the port omits. Extraction ran on four RTX 2080 Ti GPUs of the IIIT-H Ada cluster, and all \nExtracted{} files completed with consistent artifacts. Six of eight original fidelity gates passed; two failed (tokenizer EOS and a random-byte threshold). The amended checks, which use the actual BOS-plus-byte input and require over 90\% random-byte boundary density, pass. Rerun on the cluster's software stack, the amended gate set \FidelityAda{}. This establishes agreement with an independent reference implementation, not identity with the original weights.

Every corpus byte was restored and verified against the stored sha256 before inference, and derived parses were built only from verified bytes. Tree-sitter error recovery triggers on 28.1\% of C++ files (unresolved macro and header context); these files are retained and flagged rather than dropped, because recovery is localized and excluding them would bias the sample toward simpler files. The confound that motivates the structure-blind baselines is measured, not assumed: 31.8\% of Python and 22.5\% of C++ constituent starts sit exactly at an indentation-change byte, so a proposer that splits at line or indentation boundaries would score well without knowing anything about grammar. Saved outputs are reproducible: cross-process reruns of the same bytes agree to within $8.3\times10^{-6}$ nats with identical boundary sets, so every downstream table can be recomputed from the retained per-byte arrays. Files longer than 8{,}191 bytes cross an 8{,}192-token chunk boundary, after which the patcher's context resets; these bytes are identified per file in the run metadata and constitute a measured replication artefact rather than an unmodeled one. Inference throughput is about 3{,}400 tokens per second per GPU in float32 at 1.36~GiB peak memory, so the full corpus is a few GPU-hours rather than a training run; no model training occurs at any stage.

\section{Results}
\TableMain
\paragraph{P1: alignment beyond the null.} Table~\ref{tab:main} gives held-out start alignment. The F1 margin over $H_0$ is \MarginPy{} \MarginCIPy{} in Python, \MarginCpp{} \MarginCICpp{} in C++ and \MarginEn{} \MarginCIEn{} in English. Precision/recall are \PrecPy{}/\RecPy{}, \PrecCpp{}/\RecCpp{} and \PrecEn{}/\RecEn{}. A sufficient-but-not-necessary mechanism predicts precision above recall. Precision \PrecRecAll{}. BLT proposes many more boundaries than there are targets, so most boundaries fall away from constituent starts.

The precision--recall asymmetry has a mechanical reading under the patcher. A boundary certifies only that the local next-byte distribution was flat enough to cross $\tau$; because $H\le\log B$, every entropy-triggered boundary sits where at least $e^{\tau}\approx3.8$ continuations were live. Identifier interiors, strings and comments are flat without being syntactic, so predictions vastly outnumber targets and precision is structurally capped, while the same density guarantees high recall against the comparatively sparse target set. The asymmetry itself is therefore expected on entropy grounds; what the proposal's mechanism predicted - that cheap interiors and forced closing delimiters would push precision above recall - is not supported. On magnitude: a margin of roughly 0.12--0.13 F1 against a null that already shares the file's own patch-length distribution is a strong density-independent effect, but it is smaller than the 0.24--0.27 gap by which structure-blind segmentation beats BLT, which is the comparison the structural claim must survive.

\TableBaselines
\paragraph{Baselines.} The strongest structure-blind proposer is the \StrongestPy{} baseline for Python (F1 \StrongestFonePy{}), the \StrongestCpp{} baseline for C++ (\StrongestFoneCpp{}) and the \StrongestEn{} baseline for English (\StrongestFoneEn{}). BLT \RTwoAll{} (Python \VsBasePy{} \VsBaseCIPy{}; C++ \VsBaseCpp{} \VsBaseCICpp{}; English \VsBaseEn{} \VsBaseCIEn{}). With the frozen $k=0$, the newline baseline scores near zero: an indented statement starts after its indentation, not at the byte after the newline, and each English sample is a single paragraph. A margin over $H_0$ that does not survive this comparison indicates line or word segmentation rather than syntactic structure. The scale of the confound is known before scoring: 31.8\% of Python and 22.5\% of C++ constituent starts sit exactly at an indentation-change byte, and English constituent starts largely coincide with word starts, which is why the indentation and word baselines dominate in their respective languages.

\paragraph{P2 and P3.} The start margin \PTwoAll{} (end margins \EndMarginPy{}, \EndMarginCpp{} and \EndMarginEn{} for Python, C++ and English). These two margins share predictions and are compared descriptively. Pooled by domain, the code margin (\MarginCode{}) is \PThreeCmp{} the prose margin (\MarginProse{}), so P3 is not supported; in English, BLT also falls short of the word-start baseline (Table~\ref{tab:baselines}). Mean bytes per patch are \BppPy{}, \BppCpp{} and \BppEn{} (Python, C++, English), with mean within-file BPP variances \BppVarPy{}, \BppVarCpp{} and \BppVarEn{}. The large C++ variance is interpretable: C++ files mix long boilerplate stretches (headers, declarations, brace blocks) with dense logic, so within a single file the patcher alternates between long cheap patches and short uncertain ones, whereas prose paragraphs are comparatively homogeneous. The code--prose contrast therefore goes the opposite way from the proposal's prediction: prose, not code, produces the largest margin over the null.

\TableTypes
\paragraph{P4 and depth.} Averaged over types, the recall margin over $H_0$ for forced-opener constructs is \DetMarginPy{} in Python and \DetMarginCpp{} in C++, against \OpenMarginPy{} and \OpenMarginCpp{} for open-ended ones (Table~\ref{tab:types}). The forced-opener margin \PFourAll{}, so the data \PFourSupported{} P4 as stated. One reading is that a start boundary precedes the keyword, where the choice of statement is still open; the forcing we predicted applies to the bytes after it, which starts do not measure. Figure~\ref{fig:depth} shows the start recall margin by tree depth. The margin is large at every reported depth in both languages - 0.43--0.71 in C++ and 0.51--0.71 in Python through depth 15 - and declines only slowly toward the leaves, so boundaries track constituents throughout the tree rather than only at statement level. Raw depth is not comparable across languages (grammar scaffolding differs), which is why depth curves are within-language evidence here.

\TableIoU
\paragraph{Secondary: span IoU.} For each unique constituent span we take its best IoU with a single patch (Table~\ref{tab:iou}). BLT exceeds the null by \IouVsNullPy{} \IouVsNullCIPy{} in Python, \IouVsNullCpp{} \IouVsNullCICpp{} in C++ and \IouVsNullEn{} \IouVsNullCIEn{} in English. In code, line segmentation matches spans far better (\IouLinePy{} and \IouLineCpp{}). Word segmentation also matches spans at least as well as BLT in C++ and English (\IouWordCpp{} vs.\ \IouBltCpp{} and \IouWordEn{} vs.\ \IouBltEn{}), another instance of the segmentation confound measured on the secondary metric. Patches are much shorter than most constituents, so IoU understates alignment by design; it is secondary to start P/R.

\TableOFour
\paragraph{Objective 4: robustness to code noise.} On \OFourFiles{} held-out files per language we inject the four noise types of our proposal, each on its own: missing statement semicolons (C++), a one-space indentation change on \OFourRate{} of lines, consistent camelCase$\leftrightarrow$snake\_case renaming of \OFourCaseRate{} of convertible identifiers, and adjacent-letter swaps in \OFourRate{} of keywords. Targets are the clean constituents mapped to their noised offsets, so we measure whether boundaries still track the intended structure. The margin over $H_0$ is \OFourCleanPy{} (Python) and \OFourCleanCpp{} (C++) on clean code (Table~\ref{tab:o4}). The largest drop comes from \OFourWorstPy{} noise in Python (\OFourWorstDmPy{} \OFourWorstDmCIPy{}) and \OFourWorstCpp{} noise in C++ (\OFourWorstDmCpp{} \OFourWorstDmCICpp{}); every noised margin stays at or above \OFourMinMarginPy{} and \OFourMinMarginCpp{}. Patching thus degrades gracefully rather than failing. Keyword typos change BPP most (\OFourDbppPyTypo{} and \OFourDbppCppTypo{} bytes per patch), since misspelled keywords are unpredictable and receive more patches. Renaming identifiers costs almost nothing, which is consistent with the precision analysis above: identifiers are already near-arbitrary for the patcher, so renaming them does not redistribute much entropy.

\paragraph{Objective 5: status.} The memory-unsafe analysis is reported as work in progress. Its design is fixed: region spans for dereference, address-of, \texttt{new} and \texttt{delete} are extracted with tree-sitter queries, and per-region boundary density and inverse bytes-per-patch are regressed on a memory-unsafe indicator together with identifier-entropy controls on the held-out C++ split. The design matrices and region annotations are computed and retained with the run, but the inferential reading is deferred to the final submission pending a label audit. The framing matters: a pointer token is short, frequent and lexically predictable, so any effect is expected to flow through surface unpredictability rather than semantics.

\paragraph{Objectives summary.} P1 (alignment beyond the null) is supported in all three languages; P2 (starts over ends) is supported with negative end margins; the structure-blind comparison, P3 and P4 as originally stated are not supported; O4 (graceful degradation under noise) is supported. The pattern is consistent with entropy being a genuine but shallow structural signal: the patcher tracks constituent starts far beyond chance, but most of what it tracks is line and word segmentation, and the parts of the hypothesis that required entropy to distinguish grammatical choice from lexical novelty did not survive the held-out test.

\section{Remaining Work and Conclusion}
BLT's entropy boundaries sit at constituent starts far more often than its own patch lengths would by chance. Relative to the strongest structure-blind baseline, however, BLT \RTwoAll{}. Any structural claim must therefore be made relative to line and word segmentation, not the null alone.

\section*{Limitations}
The checkpoint is a third-party conversion, and the sliding window was restored by us. The restoration is validated against an independent reference implementation of the same weights - agreement is architectural and behavioral (logit agreement to $1.05\times10^{-4}$, exact boundary agreement) rather than bitwise with the original FAIR checkpoint, which is gated. English targets come from predicted benepar parses, so the English ground truth carries the parser's error rate, and the English paragraphs were inspected in an earlier exploratory analysis before this protocol was frozen. About 28\% of C++ files trigger parser error recovery; they are included and flagged, which preserves representativeness at the cost of noisier targets for those files. Python samples are functions that may share repositories, so file bootstraps need not generalize across projects; the cluster bootstrap treats files as the independent unit and would underestimate variance if within-project correlation matters. The null fixes the final patch so that file end never becomes a scored boundary; word and newline baselines are deterministic and not density matched, so they are stronger comparisons than a density-equalized alternative would be. Objective 4 uses one noise rate per type and 1{,}000 null permutations per file, and span IoU uses 100. Files longer than 8{,}191 bytes have chunk-reset positions whose context is truncated; these are reported per file in the run metadata.

The project analyzes existing text and source code without executing corpus programs. Dataset provenance and licenses accompany restored inputs; CodeSearchNet carries no per-file license.
